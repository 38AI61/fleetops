1. **Deliver writes `jobs.delivery_geom`** (proposal: yes). The column exists since 009 (D-26); P10 explicitly left the writer to P12; README §2.1.5 says "coordinates captured at delivery". The deliver UPDATE writes `state='delivered'`, `delivery_geom = ST_SetSRID(ST_MakePoint(lng, lat), 4326)::geography`, `delivered_at = now()`, and `proof_photo = <key>` in ONE statement inside the same tx (the trigger permits non-assignment column changes alongside a state change — GF-171). Verify the trigger really permits it in G0.
2. **Which job responses carry the presigned URL** (proposal: uniform rule). The GF-173 job object gains one field `proof_photo_url` (string or null): every endpoint that emits the job object emits it — non-null iff `jobs.proof_photo` is non-null, computed server-side at read time (signed on read, never stored, TTL 15 min). Covers dispatcher `GET /jobs`, `POST /jobs`, assign, cancel, driver `today`, and every driver transition response. When the proofs store is nil (tests/legacy harness), the field is null and nothing breaks. `delivery_geom` is NOT emitted (no consumer yet; GF-173 precedent of not emitting unwired columns).
3. **MinIO client library** (proposal: `github.com/minio/minio-go/v7`). tech-stack §2 pins the testcontainers MinIO module but names no client; minio-go/v7 is the canonical S3 client for MinIO, smaller than aws-sdk-go-v2. New direct requires: minio-go/v7 + testcontainers-go/modules/minio (same v0.44.0 line as the other modules). go.mod/go.sum changes are in scope this phase.
4. **Size and MIME enforcement points** (proposal: two layers, MIME sniffed not trusted). (a) Route-level `middleware.BodyLimit("8M")` on deliver only — 5 MiB photo + multipart framing; global 64K untouched for every other route; oversized requests die at the middleware with 413. (b) Handler-side (authoritative): parse multipart; the file part must be ≤ 5 MiB (5 × 1024 × 1024 bytes — state the byte count in the spec); MIME decided by `http.DetectContentType` over the first 512 bytes of the part content (the declared Content-Type is not trusted); sniffed `image/jpeg` → ext `jpg`, `image/png` → `png`, `image/webp` → `webp`; anything else → 400. Error mapping: oversize → 413 (matches the BodyLimit behavior; record it as a deliberate extension of the GF-178 vocabulary), wrong MIME / missing part / bad lat-lng → 400 `validation_failed`. Decide and record exactly this.
5. **Short-TTL expiry test hook** (proposal: injectable field, not env). The proofs presigner carries a `PresignTTL time.Duration` defaulting to 15 min; tests construct it with 1–2 s to exercise real expiry (GET 200 → wait → 403 AccessDenied). No `FLEETOPS_*` env var is added (the D-22 list is untouched; README fixes 15 min).
6. **Deliver endpoint contract** (proposal): multipart form fields `photo` (file), `lat`, `lng` (text); lat ∈ [-90, 90], lng ∈ [-180, 180] (GF-173 point ranges); object filename `<uuidv4>.<ext>` (google/uuid, already pinned); success → `200` with the job object including a fresh `proof_photo_url`; deliver from a state other than `picked_up` → 409 before any upload; other driver's / cross-fleet job → 404 before any upload (GF-187 guard runs first); replay (job already `delivered`) → 200 with no event, no upload, the response presigns the existing `proof_photo`. Applied deliver publishes one `job.updated` after commit (GF-191 pattern, `driver_id` non-null). Concurrent-deliver loser may leave one orphan object (winner's key is the referenced one) — record as accepted MVP behavior, no cleanup.
