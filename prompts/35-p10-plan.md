Scope facts (from roadmap P10 — the plan must cover exactly these, nothing more):

- **Migration 009** creates the `jobs` table per README §5 exactly (columns, `(fleet_id, state)` index) plus the D-26 additive columns (`notes`, `size_class`, `weight_kg`, `delivery_geom geography`, `failure_reason`); `job_events` append-only via trigger (R-7, migration-003 idiom); `job_transitions` reference table seeded with every D-23 edge; one `BEFORE UPDATE` trigger on `jobs` that rejects invalid transitions (SQLSTATE) and writes `job_events` with the actor from `SET LOCAL app.actor_id` (D-24). Down migration drops all of it. GF-5 rules apply (no `BEGIN`/`COMMIT`, sequential numbering, round-trip test must stay green).
- **`internal/jobs/transitions.go` is the single source** of the transition table (D-23); `job_transitions` mirrors it; a test must prove the mirror (DB rows == Go edges).
- **Dispatcher endpoints** (JWT): `POST /jobs`, `GET /jobs` (filters: state, driver, day), `POST /jobs/:id/assign` — assign from `created`, also reassign while `assigned` — and `POST /jobs/:id/cancel` (SPEC-AMEND). All fleet-scoped by the token's `fleet_id`; cross-fleet job/vehicle/driver → 404.
- **D-24 idempotency**: `UPDATE … WHERE id=$1 AND state=$from`; zero rows and current state == target → 200 with no new event; otherwise 409. Replaying the last transition returns 200 with no new event. Illegal transitions return 409 and persist nothing.
- **Publish `jobs.events.<fleet_id>` per successful transition** on core NATS (GF-4, no JetStream stream), body compatible with the hub envelope contract above; durable record is `job_events` in PG, delivery is best-effort.
- **`mapview.JobLookup` implementation** wired in `server.go` (GF-133): vehicles with an `en_route`/`picked_up` job display `en_route` on the map.
- Role-matrix rows for the four new endpoints are added to the §8 test (R-6).
