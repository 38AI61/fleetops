Scope facts (from roadmap P19 — the plan must cover exactly these, nothing more):

- **`alert_rules` table** (migration `011_*`): three fixed kinds seeded per fleet with spec defaults (`device_silent` 10 min, `eta_slip` 15 min, `geofence_exit_outside_schedule` schedule window); parameters configurable, kinds are not (D-08).
- **`alerts` append-only with one-time ack transition (trigger)**: `acked_by`/`acked_at` `NULL → value` once; second ack rejected; DELETE forbidden (D-09, migration `011_*`).
- **`GET /alerts?since=`** and **`PATCH /alerts/:id/ack`** (JWT; role matrix per README §8 — check what the P17 matrix established and follow it).
- **`GET /alert-rules` / `PATCH /alert-rules`** (admin, manager only).
- **`device_silent` evaluator**: last `server_ts` older than 10 min → one alert per silence episode, re-arms on the next report (warning).
- **`geofence_exit_outside_schedule`**: consumes P18 `exit` events; applies the fence `schedule` (`{days, from, to, tz}`) in `fleets.timezone` (critical). Schedule evaluation is the only schedule logic in P19.
- **`alert.raised` on WS** via `alerts.<fleet_id>` (core NATS per GF-4; hub subscribes and fans out).
- **`Notifier` stub** (D-11): critical alerts → managers; logs event type and user id only, never the address.
- **Notification bell UI** in `apps/web`: unacked count, list, ack action.
